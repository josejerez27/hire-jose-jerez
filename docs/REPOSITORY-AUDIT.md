## Vercel 404 findings

The public homepage linked from GitHub, `https://hire-jose-jerez.vercel.app/`, returned HTTP 404 with Vercel's `NOT_FOUND` page during inspection.

The repository already contained a valid homepage route. There is no evidence that a missing `page.tsx` caused the public error. The exact deployment cause cannot be established without Vercel's project settings, deployment history, domain assignments, and build logs.

Check the following in Vercel:

1. The project is connected to `josejerez27/hire-jose-jerez`, production branch `main`.
2. Root Directory is the repository root containing `package.json`, not `src`, `src/app`, or this surrounding `sn-playwright` workspace.
3. Framework Preset is Next.js; build is `npm run build`; install is `npm ci`.
4. Output Directory has no manual override. Let the Next.js integration select the output. Do not set it to `public`, `out`, or `build`.
5. A successful production deployment exists, and the intended `.vercel.app` domain belongs to that project and deployment. Compare the deployment-specific URL with the production alias.
6. Inspect a failed deployment's Build Logs before concluding that the source is at fault. Redeploy the corrected commit and assign/promote the successful deployment to production if necessary.

The new `vercel.json` explicitly selects Next.js and the repository scripts. It cannot repair a deleted project, an incorrect domain assignment, or settings in an inaccessible account.

References: [Vercel NOT_FOUND](https://vercel.com/docs/errors/not_found), [Next.js on Vercel](https://vercel.com/docs/frameworks/full-stack/nextjs).
